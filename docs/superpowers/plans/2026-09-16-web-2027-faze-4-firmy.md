# Fáze 4: Stránka pro firmy — implementační plán

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Postavit `/firmy` — jednu stránku se třemi nabídkami pro tři různé lidi ve firmě a s jedním poptávkovým formulářem, který firemní dotazy oddělí od rodičovských.

**Architecture:** Obsah tří nabídek žije v datovém modulu `src/lib/firmy.ts`, ne v JSX — tým ho pak upravuje na jednom místě a testy můžou hlídat, že se do něj nedostalo vymyšlené číslo nebo reference. Stránka je serverová a skládá se z hotových kusů; klientský je jen formulář, protože potřebuje stav. Formulář míří do existujícího `/api/contact`, které dostane příznak typu poptávky — jeden kanál se třemi režimy, ne tři formuláře.

**Tech Stack:** TypeScript, Next.js 16 (App Router), Tailwind, Framer Motion, Vitest 2, Formspree, weeks-hub.

**Spec:** `docs/superpowers/specs/2026-09-15-web-2027-design.md`, oddíl „Stránka pro firmy"

## Global Constraints

- Veškerý text pro uživatele je **česky**, vykáním. Kód a komentáře taky česky.
- **Tón: střízlivý a věcný. Prodejní duch ano, marketingová vata ne.** Žádná superlativa, žádné „revoluční" ani „jedinečné".
- **Nevymýšlej reference, ceny ani počty odbavených firem.** Kde by bylo potřeba konkrétní číslo nebo jméno, zůstane v datech zřetelná mezera a napíše se do reportu jako otázka pro majitele. Weeks zatím **žádnou firemní zakázku neodbavil** — stránka to nesmí zastírat.
- **Weeks s.r.o. je neplátce DPH** — nikde se nevyčísluje daň.
- Identita se bere ze `src/lib/site.ts`, nikdy natvrdo.
- **HWLab Praha není domluvený a FabLab VARY&TE nemá podepsané partnerství.** Ani jeden se nesmí uvádět jako partner.
- Nedokládej nic, co web nedokládá jinde — žádné pojištění účastníků, žádné certifikace, žádné sliby doby odezvy. Doložitelné je: poměr jeden lektor na pět dětí, proškolení v první pomoci (doslovně z `getSiteFaq()`), kapacita odvozená z dat.
- Vizuální jazyk „maker lab": `bg-paper` / `bg-ink`, rámečky `border-ink/15`, mono popisky `mono-label`, mřížka `blueprint-grid`.
- Animace respektují `prefers-reduced-motion` (`useReducedMotion` z Framer Motion).
- Přístupnost: každý input má svázaný `<label>`, prvek bez viditelného textu `aria-label`, obrázky `alt` a mimo první obrazovku `loading="lazy"`, chybová hláška formuláře v `aria-live`.
- Metadata: každá stránka s vlastním blokem `openGraph` **musí nést i `images`** — Next slučuje metadata mělce a blok bez obrázku přebije kořenový. Vzor je `src/app/kontakt/layout.tsx`.
- `npm run lint` je rozbité (Next 16 zrušil `next lint`). Bránou je `npm test`, `npx tsc --noEmit` a `npm run build`.
- **Nikdy `git add -A`** — v kořeni repozitáře leží soukromé soubory mimo verzování.

## Jak se řeší „zřetelná mezera"

Specifikace žádá, aby tam, kde chybí skutečné číslo nebo jméno, zůstala zřetelná mezera
k doplnění. Mezera viditelná návštěvníkovi by ale byla horší než chybějící obsah.

Řešení: mezera je **zřetelná v datech, neviditelná na stránce**. `src/lib/firmy.ts` má
u každé nabídky nepovinná pole (`reference`, `cenaOd`, `odbavenoFirem`), která jsou dnes
prázdná a komponenta je při prázdné hodnotě **nevykresluje vůbec**. Nad nimi stojí
komentář, co se do nich má doplnit a kdo to ví. Tým vidí mezeru v jednom souboru,
návštěvník nevidí nedodělek.

```ts
import { describe, it, expect } from 'vitest'
import { parseContactBody } from './contact-payload'

const zaklad = { name: 'Jana Nováková', email: 'jana@firma.cz', message: 'Dobrý den, ...' }

describe('parseContactBody', () => {
  it('bez typu jde o běžný kontaktní dotaz', () => {
    const r = parseContactBody(zaklad)
    expect(r.ok).toBe(true)
    if (r.ok) expect(r.data.formType).toBe('contact')
  })

  it('firemní poptávka nese svůj typ', () => {
    const r = parseContactBody({ ...zaklad, typ: 'workshopy', firma: 'Firma s.r.o.' })
    expect(r.ok).toBe(true)
    if (r.ok) {
      expect(r.data.formType).toBe('firmy')
      expect(r.data.typ).toBe('workshopy')
      expect(r.data.firma).toBe('Firma s.r.o.')
    }
  })

  it('odmítne neznámý typ poptávky', () => {
    const r = parseContactBody({ ...zaklad, typ: 'cokoliv' })
    expect(r.ok).toBe(false)
  })

  it('odmítne chybějící povinné pole', () => {
    expect(parseContactBody({ ...zaklad, name: '' }).ok).toBe(false)
    expect(parseContactBody({ ...zaklad, email: '' }).ok).toBe(false)
    expect(parseContactBody({ ...zaklad, message: '' }).ok).toBe(false)
  })

  it('odmítne neplatný e-mail', () => {
    expect(parseContactBody({ ...zaklad, email: 'neni-email' }).ok).toBe(false)
  })

  it('předmět e-mailu rozliší firemní poptávku od rodičovské', () => {
    const bezny = parseContactBody(zaklad)
    const firemni = parseContactBody({ ...zaklad, typ: 'partnerstvi' })
    if (bezny.ok && firemni.ok) {
      expect(firemni.data.subject).not.toBe(bezny.data.subject)
      expect(firemni.data.subject.toLowerCase()).toContain('firm')
    }
  })

  it('ořízne přepálené vstupy, ať se do e-mailu nedá nacpat cokoliv', () => {
    const r = parseContactBody({ ...zaklad, message: 'x'.repeat(10000) })
    expect(r.ok).toBe(true)
    if (r.ok) expect(r.data.message.length).toBeLessThanOrEqual(5000)
  })
})
```
