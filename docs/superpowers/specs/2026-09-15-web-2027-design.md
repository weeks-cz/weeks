# Weeks web 2027 — přestavba

**Datum:** 2026-09-15
**Větev:** `feat/web-2027`
**Stav:** schválený návrh, fáze 0 hotová

## Proč

Tři změny dopadly na web najednou a každá sama o sobě by byla záplata. Dohromady
dávají smysl jako jedna přestavba:

1. **Vizuál.** Tým schválil redesign „maker lab" (větev `design/maker-lab`,
   hotový 2026-07-03). Dosud nenasazený.
2. **Provozovatel.** Vznikla Weeks s.r.o. (IČO 29984360, zapsaná 2026-09-03).
   Spolupráce s DDM Praha 6 končí — DDM musí z webu zmizet, a to včetně
   chování, které na něm viselo (externí registrace, scraping obsazenosti).
3. **Nabídka.** Víkendové i jednodenní tábory končí. Zůstává letní příměstský
   tábor (formát odzkoušený v Karlových Varech) plus nová B2B linka. Města
   přestávají být oddělenými větvemi webu — sjednocují se a volba města se
   přesouvá až k termínu.

Dnešní web je postavený jako katalog programů se dvěma paralelními stromy
stránek podle města. Nová nabídka je jeden produkt s turnusy. To není úklid,
ale jiný datový model.

## Rozsah

**Uvnitř:** informační architektura a URL, datový model turnusu, výběr tábora,
odchod od DDM, identita Weeks s.r.o., stránka pro firmy, mimosezónní stav.

**Mimo:** e-shop, učebna (iot.weeks.cz), hub (app.weeks.cz), platební a
fakturační napojení. Převod Comgate/Fakturoid/účtu z OSVČ na s.r.o. je
provozní úkol mimo tento repozitář, ale musí proběhnout dřív, než se pod
s.r.o. začne prodávat.

## Datový model

### Problém, který řeší

Turnus má dnes tři zdroje pravdy:

- karlovarské termíny staticky v `locations.ts` (`terms[]`),
- pražské termíny v Supabase tabulce `camps` (částečně scrapované z DDM),
- cena a kapacita v `programs[]`, odkud si je bere registrační API přes
  `getTrustedCapacity(location_id, program)`.

Stránka turnusu tak může ukazovat něco jiného, než co si myslí registrace.

### Řešení

Jedna entita, definovaná v repozitáři:

```ts
// src/lib/turnusy.ts
export type CityId  = 'praha' | 'karlovy-vary'
export type FocusId = '3d-tisk' | 'iot' | 'vr' | 'herni-vyvoj'

export interface Turnus {
  id:       string        // stabilní klíč → registrations.term_id, NIKDY neměnit
  slug:     string        // 'karlovy-vary-cervenec-2027' → /tabor/[slug]
  city:     CityId        // → registrations.location_id
  venue:    Venue | null  // null = místo ještě není domluvené
  start:    string        // ISO
  end:      string        // ISO
  priceKc:  number
  capacity: number
  status:   'chystame' | 'otevreno' | 'plno' | 'uzavreno'
  focus:    FocusId[]     // řídí obsah stránky turnusu
  perex?:   string        // čím je tenhle turnus jiný
}
```

**Město se scvrkne na číselník.** Dnešní `Location` nese vlastní programy, USP,
FAQ, hero texty a seznam dostupných stránek — celý paralelní web. Nově zbude
název, kraj a souřadnice pro strukturovaná data.

Zbytek se rozdělí podle toho, čí vlastnost to doopravdy je:

- **vlastnost turnusu** — místo konání, cena, kapacita, věkové rozmezí, zaměření
- **vlastnost webu** — kontakt (telefon a e-mail jsou stejné pro obě města),
  FAQ, popisy pro vyhledávače, hero texty. Přesouvá se do jedné globální
  konfigurace webu, protože po sjednocení už se podle města neliší.

**Cena a kapacita patří turnusu.** Registrační API dostane `term_id`, dohledá
turnus a z něj si vezme cenu i limit. Jedno vyhledání místo tří, a turnusy s
odlišným zaměřením můžou mít odlišnou cenu.

**Zaměření je znovupoužitelný obsahový modul.** Každé `FocusId` má svůj kus
obsahu (co si dítě vyzkouší, fotky, ukázky projektů). Turnus si ho přitáhne.

**Přístup přes tenké rozhraní.** Stránky čtou výhradně přes `getTurnusy()`,
`getTurnus(slug)` a `getCities()`. Zdroj dat je za tímto rozhraním schovaný,
takže pozdější přesun turnusů do hubu (app.weeks.cz) je výměna implementace,
ne přestavba stránek. Tým to zatím chce v kódu; hub je uvažovaná budoucnost.

**Živá kapacita zůstává v databázi.** `/api/term-capacity` počítá obsazenost z
tabulky `registrations` podle stejného pravidla, které vynucuje
`create_registration()` (migrace 011). Změní se jen to, že iteruje nad turnusy
místo nad `location.terms`.

### Zpětná kompatibilita

Do databáze se dál ukládá `city` jako `location_id` a `id` turnusu jako
`term_id`. Existující registrace, faktury a pohled v hubu zůstanou čitelné.
Nic se nepřepisuje ani nemigruje.

Tabulka `camps` zůstane v databázi kvůli historii a hubu, ale veřejný web z ní
přestane číst.

## Výběr tábora

Dnešní cesta je tři rozhodnutí, než rodič uvidí datum: město v přepínači →
program v mřížce → termíny na stránce programu. Přepínač měst navíc nabízí
Prahu i Vary rodiči, který ví, kde bydlí.

Nová cesta je jedno rozhodnutí: **vyber turnus.**

Pravidla:

1. **Filtr měst se zobrazí, jen když jsou turnusy ve dvou a více městech.**
   Jeden turnus v jednom městě = prostý seznam. Přepínání tím mizí, aniž
   bychom o tu možnost přišli při expanzi.
2. **Město je štítek, ne brána.** Rodič vidí i turnusy z druhého města. Je to
   lepší než dnešek, kdy se o nich nedozví.
3. **Turnus bez místa nebo bez pevného data je platný stav.** Zobrazí se
   čárkovaně jako „chystáme", bez ceny, se sběrem kontaktu. Praha bez
   domluveného prostoru tak nemusí ani lhát, ani mlčet.
4. **Karta turnusu je jedna komponenta pro tři místa** — úvodka (nejbližší
   dva), `/tabor` (všechny), patička detailu turnusu (další termíny).

Filtrování podle věku a zaměření se nedělá. Při dvou až šesti turnusech za
sezónu je to práce navíc nad seznamem, který se vejde na obrazovku.

Filtr měst na `/tabor` je stav v adrese (`?mesto=karlovy-vary`), ne jen v
paměti stránky — aby šel odkaz na předfiltrovaný seznam poslat i použít v
reklamě. Kanonická adresa `/tabor` přitom zůstává bez parametru, ať filtrované
varianty nekonkurují samy sobě ve vyhledávání. Vlastní stránku s vlastní
kanonickou adresou má až turnus.

### Mimosezónní stav je výchozí, ne výjimka

Web se spouští do mrtvé sezóny: letní turnusy 2027 půjdou na web nejdřív koncem
října 2026. V den nasazení tedy nebude k prodeji ani jeden turnus.

Hlavní výzva k akci proto při spuštění není „přihlásit", ale „nechte kontakt,
ozveme se mezi prvními". Komponenta existuje — off-season panel nasazený na
Karlovy Vary v červenci 2026 (`SeasonConfig`, commit `0f6dad1`). Mění se jen
to, že z výjimky pro jedno město se stává výchozí chování webu, řízené stavem
turnusů místo konfigurací lokality.

### Sekce důvěry

Dnešní pruh partnerů (DDM + HWLab v poměru 1:5) si půjčoval cizí důvěryhodnost.
DDM odchází, HWLab v Praze není domluvený a spolupráce s FabLab VARY&TE není
podepsaná jako partnerství. Uvádět kohokoliv z nich jako partnera by bylo
tvrzení bez opory.

Pruh log proto nahradí sekce **„Kde a s kým"**, stojící na ověřitelném:
skutečné fotky z tábora, čtyři členové týmu jmenovitě s tím, co kdo dělá,
poměr jeden lektor na pět dětí, a vybavení FabLabu popsané jako **místo, kde
tábory probíhaly** — což je fakt, ne nárok na partnerství. Až bude něco
podepsané, logo se přidá na připravené místo.

### Mimo web

Dvě věci na stejném rozhodnutí visí, ale do repozitáře nepatří:

- **Právní texty si musí projít tým.** Mění se správce osobních údajů, což je
  skutečná právní změna, ne formulace.
- **Zotavovací akce.** Pod DDM se ohlášení hygieně, zdravotník a posudky vezly
  na jejich hlavičce. Tábor ve vlastní režii to má na sobě. Na web to patří jen
  jako věta v podmínkách.

## Stránka pro firmy

Tři nabídky na jedné stránce, protože mluví na tři různé lidi:

```
/firmy
├── Hero ......... jedna věta, co firmám nabízíte, + kotvy na tři nabídky
├── Dny pro děti zaměstnanců ... HR / benefity
│   pro koho · jak to probíhá · co zajistíte vy, co my
├── Workshopy a teambuilding ... office manager / vedoucí týmu
│   3D tisk, IoT, VR jako zážitek · délka · velikost skupiny
├── Partnerství a sponzoring ... marketing / vedení
│   co za to firma má · jak to vypadá v praxi
├── Kde a s kým .. prostory, tým, čím jsme prošli
└── Poptávka ..... jeden formulář, přepínač „co vás zajímá"
```

Tón: střízlivý a věcný, prodejní duch ano, marketingová vata ne.

Obsah je **návrh k redakci týmu**. Reference, ceny ani počty odbavených firem
se nevymýšlejí — kde je potřeba konkrétní číslo nebo jméno, zůstane zřetelná
mezera k doplnění.

V každé nabídce stojí explicitně „co zajistíte vy, co my". To je věta, kvůli
které HR odpoví: rodič kupuje pocit bezpečí pro dítě, HR kupuje něco, co
obhájí před vedením a co ho nebude stát čas.

Formulář míří do existujícího `/api/contact` s příznakem typu poptávky, ať se
firemní dotazy neztratí mezi rodičovskými. Jeden kanál se třemi režimy, ne tři
formuláře — méně kódu a jedno místo, kde se poptávka může ztratit.

## Postup

Pořadí je dané závislostmi. Mazání stránek jde záměrně před úklidem DDM,
protože většina zmínek o DDM sedí ve stránkách, které stejně zanikají.

| Fáze | Obsah | Stav |
|---|---|---|
| 0 | Větev `feat/web-2027`, merge `design/maker-lab`, ověřený build | **hotovo** |
| 1 | Datový model: `turnusy.ts`, města jako číselník, moduly zaměření, registrační API na `term_id` | |
| 2 | Struktura: `/tabor`, `/tabor/[turnus]`, přestavěná úvodka, smazané stránky, přesměrování. Součástí fáze je i vytáhnout ze zanikajících stránek (`/tabor-3d-tisk`, `/tabor-iot`) zbývající obsah — fotky, harmonogram, FAQ, úplný seznam modelů tiskáren — do modulů zaměření, a to dřív, než se stránky smažou. | |
| 3 | Odchod od DDM: identita s.r.o., právní texty, smazaný scraper a cron, sekce „Kde a s kým" | |
| 4 | `/firmy` s poptávkovým formulářem | |
| 5 | Dotažení: mimosezónní stav, sitemap, strukturovaná data, analytické události | |

Do produkce může web jít po fázi 3, i bez `/firmy` — B2B stránka se nasadí
zvlášť, až ji tým projde.

### Fáze 0 — co se stalo

Větev `feat/web-2027` z `main`, merge `design/maker-lab` (commit `3d5e213`).
Šest konfliktů, všechny ze stejné příčiny: na `main` mezitím přibyla logika
konce sezóny (`seasonEnded`), kterou větev designu nezná. Vyřešeno sloučením —
struktura a tokeny z maker-labu, podmínky sezóny z `main`. Build i `tsc`
procházejí.

## Otevřené vstupy od týmu

- Místo konání v Praze. HWLab je přání, ne dohoda. Do té doby turnus bez místa.
- Obsah tří B2B nabídek — co přesně se firmám slibuje.
- Kontrola právních textů po změně správce osobních údajů.

## Poznámky

- `npm run lint` je rozbité napříč repozitářem (Next 16 zrušil `next lint`,
  chybí `eslint.config`). Build je jediná brána. Předchozí stav, netýká se
  této práce.
- Registrační data v databázi se nemigrují. Klíče `location_id` a `term_id`
  zůstávají ve stejném tvaru.
